# سامانهٔ مانیتورینگ لحظه‌ای تغییرات وب‌سایت (نسخهٔ ۲)

این برنامه سایت‌های موردنظر شما (سفارت‌خانه‌ها، صفحات ویزا و نوبت‌دهی، سایت‌های خبری، RSS و کانال‌های عمومی تلگرام) را مداوم بررسی می‌کند و **هر تغییری** را با جزئیات کامل در تلگرام گزارش می‌دهد: چه متنی اضافه شد، چه متنی حذف شد، و در خطوط ویرایش‌شده دقیقاً کدام کلمه با کدام کلمه جایگزین شد.

```
🚨 تغییر در «سفارت آلمان (تهران)»
🕒 دوشنبه ۱۳ مهر ۱۴۰۵ — ساعت ۱۵:۴۶
🔗 teheran.diplo.de/ir-fa
📊 خلاصه: 🟢 ۲ جدید · 🔴 ۱ حذف · 🟡 ۱ ویرایش · 🔗 ۱ لینک تازه
🔑 کلمات کلیدی: Termin
━━━━━━━━━━━━━━
📍 Visastelle
┃ 🟡 Termine für nationale Visa ab ~~15.~~ **20.** Oktober

📍 Häufige Fragen
┃ 🔴 ~~Alte Hinweise zum Antrag~~
┃ 🟢 Neue Termine für Studierende: Anmeldung ab Montag

🔗 لینک‌های تازه (۱)
┃ • Termin-Buchung für Studierende
            [ 🌐 باز کردن صفحه ]
```
(تغییرات هر بخش از صفحه زیر عنوان همان بخش، داخل کادر نقل‌قول؛ بخش‌های طولانی جمع‌شونده‌اند.)

## ویژگی‌ها

| ویژگی | توضیح |
|---|---|
| **سرعت** | موتور HTTP هر صفحه را در ۰٫۱ تا ۱ ثانیه بررسی می‌کند (حدود ۳۰ برابر سریع‌تر از مرورگر)، پس می‌توان هر ۳۰ تا ۶۰ ثانیه بررسی کرد. با «GET شرطی» (ETag) اگر صفحه عوض نشده باشد، تقریباً هیچ داده‌ای دانلود نمی‌شود. |
| **سایت‌های محافظت‌شده** | سه روش دریافت با جایگزینی خودکار: ۱) HTTP سریع؛ ۲) **شبیه‌ساز کروم** (`impersonate`) که اثر انگشت TLS یک Chrome واقعی را دارد و از Akamai و Cloudflare عبور می‌کند، با همان سرعت HTTP؛ ۳) مرورگر واقعی (Patchright) برای سایت‌های جاوااسکریپتی. اگر سایتی شروع به مسدود کردن کند، فاصلهٔ بررسی خودکار بیشتر می‌شود تا IP سرور مسدود نماند. |
| **پروکسی پشتیبان خودکار** | اگر سایتی **IP خود سرور** را مسدود کند (مثل 403 گوته)، بررسی خودکار از طریق Cloudflare WARP روی همان سرور (یا پروکسی دلخواه) تکرار می‌شود و همان مسیر برای بعد نگه داشته می‌شود. بدون هیچ تنظیمی؛ کافی است WARP نصب باشد. |
| **تیترهای جدید (سایت خبری)** | حالت `headlines` فقط خبرهای **تازه** (تیتر + لینک) را می‌فرستد؛ جابه‌جایی مطالب، «۵ دقیقه پیش»، «۸ min read» و تغییر خلاصه‌ها پیام نمی‌سازند. اگر صفحه‌ای مدام عوض شود، ربات خودش تبدیل به این حالت را پیشنهاد می‌دهد. |
| **حذف خودکار نویز** | زمان‌های نسبی («5 mins ago»، «۳ ساعت پیش»، «vor 2 Stunden»)، زمان مطالعه و پخش‌کنندهٔ ویدیو هیچ‌وقت «تغییر» حساب نمی‌شوند؛ تاریخ‌های واقعی می‌مانند. |
| **📸 عکس صفحه** | از کارت هر سایت، عکس صفحه (یا فقط بخش زیر نظر) همان‌طور که سرور می‌بیند. |
| **سایت‌های ظرفیتی (آزمون، ثبت‌نام، نوبت)** | نوع `json` داده‌های پشت صفحه (API) را مستقیم پایش می‌کند. نمونهٔ آمادهٔ **آزمون‌های گوته** وضعیت هر آزمون را دقیق گزارش می‌دهد: «⛔ تکمیل ← ✅ قابل رزرو»، «⏳ رزرو از …»، «🟢 جای خالی محدود». |
| **بیدارباش** | برای تغییرات مهم، هشدار خصوصی تا ۶ بار (هر ۴۵ ثانیه) تکرار می‌شود تا «دیدم» را بزنید؛ مناسب وقتی ساعت ۳ شب ظرفیت باز می‌شود. |
| **پوشش کل سایت** | با `crawl` همهٔ صفحات یک بخش (مثلاً همهٔ صفحات فارسی سفارت) زیر نظر گرفته می‌شود: صفحهٔ جدید، صفحهٔ تغییرکرده، صفحهٔ حذف‌شده و فایل‌های PDF جدید یا تغییرکرده. لینک جدید در صفحهٔ اصلی چند ثانیه بعد بررسی و گزارش می‌شود. |
| **اخبار** | نوع `feed` برای RSS/Atom و نوع `items` برای فهرست خبرها، اطلاعیه‌ها یا پست‌های کانال عمومی تلگرام. فقط موارد **جدید** گزارش می‌شوند. |
| **هیچ تغییری گم نمی‌شود** | هر تغییر اول در دیتابیس ذخیره و بعد ارسال می‌شود. اگر تلگرام یا اینترنت قطع باشد یا برنامه ری‌استارت شود، پیام بعداً ارسال می‌شود. حالت cooldown پیام‌ها را تجمیع می‌کند ولی چیزی را حذف نمی‌کند. |
| **گزارش دقیق** | تفاوت کلمه‌به‌کلمه، خط قبل از تغییر برای مشخص شدن محل آن، لینک‌های جدید و حذف‌شده، و فایل HTML گزارش کامل وقتی متن طولانی است. |
| **کلمات کلیدی** | مثلاً «نوبت»، «visa» یا «Termin». تغییرات حاوی آن‌ها با 🚨 مشخص می‌شوند. با `only_keywords` فقط همین تغییرات ارسال می‌شوند. |
| **ضد هشدار کاذب** | صفحهٔ خطا، صفحهٔ چالش ضدربات یا selector شکسته **هرگز** «تغییر» حساب نمی‌شوند؛ پس از چند خطای پیاپی یک هشدار و پس از رفع مشکل یک پیام «برگشت» می‌آید. جابه‌جایی خطوط و فاصله‌های اضافه نادیده گرفته می‌شوند. |
| **پنل مدیریت در تلگرام** | مثل یک اپ کوچک: منوی ثابت پایین صفحه، داشبورد، کارت هر سایت؛ افزودن، ویرایش، توقف و حذف هر تعداد سایت از چت خصوصی با ربات، بدون ورود به سرور و بدون دست زدن به `monitor-config.json`. |
| **گزارش روزانه** | هر روز یک گزارش وضعیت مرتب (سالم / نیازمند توجه / متوقف) می‌آید که نشان می‌دهد سیستم زنده است. |
| **تاریخ شمسی** | زمان‌ها به وقت تهران، با روز هفته و ماه شمسی و اعداد فارسی نمایش داده می‌شوند. |

## ✨ نسخه ۲.۲ — قابلیت‌های جدید (اکتبر ۲۰۲۶)

این نسخه شامل ۲۳ اسپرینت در چهار هفته است که قابلیت‌های زیر را اضافه کرده‌اند.

### گزارش‌های غنی‌تر (هفته ۱)

- **📈 حجم تغییر:** درصد تغییر و تعداد کاراکترهای تغییرکرده.
- **📌 بخش‌های درگیر:** فهرست بخش‌های صفحه که تغییر کرده‌اند (حداکثر ۵ مورد).
- **🏠/📂 نمایش دقیق صفحه:** تغییر در صفحه اصلی یا زیرصفحه، به‌همراه عنوان کامل.
- **heading واقعی از DOM:** گروه‌بندی تغییرات بر اساس h1 تا h6 واقعی.
- **session پایدار impersonate:** کوکی‌ها در data/sessions-impersonate نگه داشته می‌شوند.
- **هشدار کانفیگ:** ناسازگاری crawl.include با url در validate هشدار داده می‌شود.


### عکس صفحه per-watch (هفته ۲)

| تنظیم | مقدار | معنی |
|---|---|---|
| notify_mode | text / screenshot / both | متن / عکس / هر دو |
| screenshot_region | watch / page | بخش زیر نظر / کل صفحه |
| screenshot_audience | channel / admins / both | کانال / مدیران / هر دو |
| screenshot_daily | true / false | عکس روزانه |

**نحوه تنظیم:** پنل تلگرام، کارت سایت، ویرایش، دکمه‌های چرخشی.

**ذخیره‌سازی:** عکس‌ها در data/shots ذخیره می‌شوند (content-addressed).

**پاک‌سازی خودکار:** هر ۶ ساعت، عکس‌های قدیمی‌تر از ۹۰ روز حذف می‌شوند.


### سایت‌های محافظت‌شده (هفته ۳)

**Challenge Server:** برای سایت‌هایی که Cloudflare یا CAPTCHA دارند:

1. موتور browser وقتی به challenge واقعی می‌رسد، یک context زنده باز نگه می‌دارد.
2. پیامی به کانال/مدیران می‌رود با دستور SSH tunnel و URL یکبارمصرف.
3. ادمین از مرورگر خودش صفحه را زنده می‌بیند، کلیک و تایپ می‌کند.
4. با زدن حل شد، storage_state ذخیره می‌شود.

**پیکربندی در monitor-config.json:**

- challenge_host: 127.0.0.1
- challenge_port: 8899
- challenge_ttl_seconds: 600
- challenge_ssh_command: دستور SSH با IP سرور

**Rate-limit detection (Error 1015):** اگر سایت IP سرور را بلاک کرده باشد، challenge ساخته نمی‌شود و پیام موقتاً بلاک شده می‌آید.

**Adaptive Timeout:** ۲ خطای timeout پیاپی باعث دو برابر شدن timeout می‌شود (۳۰s → ۶۰s → ۱۲۰s).

**Exit-IP Diagnostics:** دکمه تست IP خروجی در کارت سایت، IP واقعی را نشان می‌دهد.


### پولیش و استحکام (هفته ۴)

- **Anchor:** هر تغییر لینک مستقیم به id عنصر دارد (پرش به بخش).
- **قبل/بعد per-watch:** report_style = inline یا before_after.
- **Diff کامل در تاریخچه:** دکمه فایل HTML کامل می‌فرستد.
- **Self-check startup:** وضعیت همه زیرسیستم‌ها در لاگ و پیام startup.
- **install_service بهبود:** tests هم روی سرور کپی می‌شود.

### هشدار لینک مهم حذف‌شده

اگر لینک حذف‌شده با کلمات کلیدی match کند، در header گزارش برجسته می‌شود.

## مدیریت سایت‌ها از ربات تلگرام (پنل مدیریت)

همهٔ کارهای روزمره از داخل تلگرام انجام می‌شود و فایل `monitor-config.json` ثابت می‌ماند (فقط توکن، کانال و تنظیمات کلی در آن است).

**چه کسی مدیر است؟** سازنده و ادمین‌های کانال یا گروهی که در `chat_ids` آمده، به‌طور خودکار. به جز آن‌ها، هر کسی ربات را باز کند پیام «این ربات خصوصی است» می‌گیرد. (فهرست اضافه: `telegram.admin_ids`)

1. ربات را در **چت خصوصی** باز کنید و `/start` را بفرستید. **منوی ثابت پایین صفحه** ظاهر می‌شود و همیشه در دسترس است:
   `📋 سایت‌ها` · `➕ افزودن سایت` · `📊 وضعیت` · `🔄 بررسی همه` · `⚙️ تنظیمات` · `❓ راهنما`
   (بعد از هر به‌روزرسانی، ربات منوی جدید را خودش برای مدیران می‌فرستد.)
2. **افزودن سایت:** لینک صفحه را بفرستید. ربات صفحه را بررسی می‌کند و حالت‌های پایش را با توضیح کوتاه پیشنهاد می‌دهد؛ بهترین گزینه با ⭐ مشخص است:
   - 📰 تیترهای جدید — برای سایت خبری: فقط خبرهای تازه
   - 🎓 آزمون‌های گوته — ظرفیت و زمان ثبت‌نام هر آزمون
   - 📄 یک بخش از صفحه / 🌐 کل صفحه — برای سفارت و دانشگاه: هر تغییر متن
   - 📌 فهرست اطلاعیه‌ها · 📡 خبرخوان RSS · 📢 کانال تلگرام
3. پیش‌نمایش را ببینید. در صورت نیاز نام، فاصلهٔ بررسی، کلمات کلیدی، بیدارباش و «خزش کل بخش» را تنظیم کنید و **✅ ذخیره و شروع** را بزنید. اولین بررسی فوراً انجام و نسخهٔ مرجع ذخیره می‌شود.
4. اگر آدرس قبلاً اضافه شده باشد، ربات هشدار می‌دهد (برای جلوگیری از سایت تکراری).
5. **سایتی که باز نمی‌شود (مثلاً 403):** ربات اول خودکار از طریق پروکسی پشتیبان (WARP) امتحان می‌کند. اگر باز هم نشد، با **«➕ افزودن به‌هرحال»** ثبت می‌شود، با فاصلهٔ امن مدام امتحان می‌شود و به محض باز شدن پیامی با دکمهٔ «🎯 انتخاب حالت دقیق پایش» می‌آید.
6. **کانال عمومی تلگرام:** فقط `@نام_کانال` یا لینک `t.me/...` آن را بفرستید.
7. **مدیریت:** «📋 سایت‌ها» ← روی هر سایت بزنید. کارت سایت: 🔄 بررسی الان، 👁 پیش‌نمایش، 📸 عکس صفحه، 🧪 تست دسترسی، 📜 تاریخچه و گزارش کامل هر تغییر، ✏️ ویرایش، ⏸ توقف / ▶️ ادامه، 🗑 حذف.
8. **ویرایش:** نام، فاصلهٔ بررسی، کلمات کلیدی، حالت پایش (بررسی دوبارهٔ صفحه)، تغییر آدرس، خزش کل بخش، پیگیری لینک‌ها، بی‌صدا، «فقط کلمات کلیدی»، پروکسی اختصاصی و روش دریافت.
9. **پشتیبان:** `/export` یک فایل json می‌دهد. برای بازگردانی یا انتقال به سرور دیگر، همان فایل را برای ربات بفرستید.
10. **آزمون گوته:** لینک صفحهٔ آزمون (مثلاً `https://www.goethe.de/ins/tr/de/spr/prf/gzb2.cfm`) را بفرستید و «🎓 آزمون‌های گوته» را بزنید. با «📍 انتخاب شهر» فقط یک شهر (مثلاً Izmir) را زیر نظر بگیرید. بیدارباش و کلمات کلیدی «قابل رزرو / جای خالی» خودکار روشن می‌شوند و باز شدن ظرفیت با «🎉 ظرفیت آزاد شد» اعلام می‌شود.
11. **🧪 تست دسترسی:** همهٔ روش‌های دریافت را **مستقیم و از طریق پروکسی پشتیبان** امتحان می‌کند و روش/مسیر موفق را با یک دکمه فعال می‌کند.

**پیام‌ها هیچ‌وقت جای هم را نمی‌گیرند:** دکمه‌های زیر گزارش‌ها (وضعیت، نتیجهٔ بررسی، تست دسترسی، تاریخچه) پیام جدید باز می‌کنند و خود گزارش در تاریخچهٔ چت می‌ماند. فقط پیام‌های پنل (داشبورد، فهرست، کارت، فرم افزودن) هنگام جابه‌جایی ویرایش می‌شوند. اگر وسط یک سؤال (مثلاً نام یا پروکسی) لینک سایتی بفرستید، سؤال لغو و آن لینک بررسی می‌شود؛ سؤال‌های بی‌پاسخ هم بعد از ۱۵ دقیقه منقضی می‌شوند.

| دستور ربات | کار |
|---|---|
| `/start` یا `/panel` | داشبورد و منوی ثابت |
| `/add` | افزودن سایت (یا فقط لینک را بفرستید) |
| `/list` | فهرست و مدیریت سایت‌ها |
| `/status` | وضعیت همه |
| `/check` | بررسی فوری همه |
| `/export` | فایل پشتیبان |
| `/cancel` | لغو کار نیمه‌تمام |

**در گروه/کانال اطلاع‌رسانی:** `/status` (وضعیت)، `/list` (فهرست سایت‌ها) و `/check` (بررسی فوری؛ فقط مدیران) همان‌جا جواب داده می‌شوند (به شکل `/status@نام_ربات` هم کار می‌کند). مدیریت سایت‌ها فقط در چت خصوصی است.

**مقصد پیام‌ها:** تغییرات سایت‌ها همیشه در کانال/گروه اعلام می‌شوند. پیام‌های سیستمی (خطا، رفع خطا، گزارش روزانه، شروع به کار، پیشنهادها) به‌صورت پیش‌فرض خصوصی برای مدیران فرستاده می‌شوند تا کانال تمیز بماند. این را در ⚙️ تنظیمات می‌توانید به «در کانال» تغییر دهید.

**سایت‌های داخل فایل تنظیمات:** سایت‌هایی که در `watches` فایل تنظیمات هستند یک بار وارد دیتابیس می‌شوند و از آن به بعد مثل بقیه از ربات قابل مدیریت‌اند. اگر یکی را در ربات حذف کنید، حذف می‌ماند؛ مگر اینکه تعریف همان سایت را در فایل تغییر دهید.

## انواع مانیتور

### `page` — یک صفحه (پیش‌فرض)، با امکان خزش کل بخش
```json
{
  "id": "de_embassy_home",
  "name": "سفارت آلمان",
  "url": "https://teheran.diplo.de/ir-fa",
  "selector": "#main",
  "track_links": true,
  "interval_seconds": 90,
  "keywords": ["ویزا", "نوبت", "visa", "termin"],
  "crawl": { "include": ["teheran\\.diplo\\.de/ir-fa/"], "max_pages": 150, "max_depth": 3, "interval_seconds": 900 }
}
```
- `selector`: فقط همین بخش صفحه مقایسه می‌شود، نه منو و تبلیغ. اگر چند عنصر را بگیرد، همه با هم بررسی می‌شوند. محتوای پنهان (آکاردئون‌ها و تب‌ها) هم شامل می‌شود.
- `track_links`: لینک‌های جدید یا حذف‌شده هم گزارش می‌شوند، حتی اگر متن لینک ثابت مانده و فقط آدرسش عوض شده باشد (مثلاً فرم PDF جدید).
- `crawl`: صفحهٔ اصلی هر `interval_seconds` بررسی می‌شود. کل بخش هر `crawl.interval_seconds` خزیده می‌شود. هر لینک جدیدی که در صفحهٔ اصلی ظاهر شود، فوراً بررسی و به‌عنوان «صفحهٔ جدید» با متنش گزارش می‌شود.

### `headlines` — تیترهای جدید یک سایت خبری
```json
{ "id": "bbc", "name": "BBC News", "type": "headlines", "url": "https://www.bbc.com/news", "interval_seconds": 120 }
```
هر لینکِ خودِ سایت که متنش شبیه تیتر باشد (حداقل ۴ کلمه) یک خبر است و با آدرسش شناخته می‌شود؛ فقط خبرهایی که **اولین بار** روی صفحه ظاهر شوند گزارش می‌شوند. منوها و لینک‌های دسته‌بندی (کوتاه) و تبلیغات (لینک به سایت‌های دیگر) نادیده گرفته می‌شوند. با `selector` می‌توانید فقط یک بخش صفحه را در نظر بگیرید.

### `items` — فهرست خبرها، اطلاعیه‌ها، کانال عمومی تلگرام
```json
{
  "id": "telegram_channel",
  "type": "items",
  "url": "https://t.me/s/bbcpersian",
  "item_selector": ".tgme_widget_message_wrap",
  "item_link_selector": "a.tgme_widget_message_date",
  "interval_seconds": 60
}
```
هر عنصرِ مطابق `item_selector` یک «مورد» است که با لینکش شناخته می‌شود. فقط موارد جدید (با عنوان، متن و لینک) گزارش می‌شوند. برای کانال تلگرام کافی است نام کانال را در `https://t.me/s/<نام>` بگذارید. `inspect` فهرست‌های مناسب هر سایت را پیدا می‌کند.

### `feed` — RSS یا Atom (سبک‌ترین و سریع‌ترین روش برای سایت‌های خبری)
```json
{ "id": "bbc_rss", "type": "feed", "url": "https://feeds.bbci.co.uk/persian/rss.xml", "interval_seconds": 60 }
```

| `interval_seconds` | `120` | فاصلهٔ بررسی (حداقل ۵) |
| `jitter_seconds` | `10` | تأخیر تصادفی اضافه برای طبیعی‌تر بودن |
| `timeout_seconds` | `30` | حداکثر زمان انتظار برای هر صفحه |
| `min_content_length` | `30` | کمتر از این تعداد کاراکتر یعنی خطا (selector شکسته یا صفحهٔ مسدود)، نه تغییر |

| `item_selector` / `item_link_selector` | — | برای `type: items` |
| `crawl` | — | `max_pages` (40)، `max_depth` (2)، `interval_seconds` (900)، `include` و `exclude` (regex روی آدرس)، `same_prefix` (true)، `track_files` (true، شامل PDF و Word و…)، `selector`، `concurrency` (2) |
| `cache_bust` | `false` | افزودن پارامتر تصادفی به آدرس برای دور زدن کش CDN |
| `persist_session` | `false` | نگه‌داشتن کوکی‌ها بین بررسی‌ها (برای سایت‌های دارای چالش) |
| `proxy` | `null` | پروکسی مخصوص همین سایت |
| `verify_ssl` | `true` | برای سایت‌هایی که گواهی SSL ناقص دارند `false` کنید |

| `wait_ms` | `0` | انتظار اضافه بعد از بارگذاری (فقط مرورگر) |

| دستور | کار |
|---|---|
| `run` | اجرای دائمی (پیش‌فرض) |

## استقرار روی سرور لینوکس (VPS، کار ۲۴ ساعته)

**روی ویندوز** بستهٔ نصب را بسازید (فقط فایل‌های لازم، بدون `.venv` و `data`) و آپلود کنید:
```powershell
.\run_windows.bat package
scp -i "<کلید>" "$HOME\Downloads\monitor-deploy.zip" ubuntu@<آی‌پی-سرور>:monitor-deploy.zip
```
**روی سرور:**
```bash
sudo apt-get install -y unzip
unzip -o monitor-deploy.zip -d monitor-src
sudo bash monitor-src/deploy/install_service.sh
```
این اسکریپت:
- یک کاربر سیستمی ایزوله (`monitorsvc`) می‌سازد.
- برنامه را در `/opt/monitor` نصب می‌کند.
- روی سرورهای کم‌حافظه (کمتر از ۲ گیگابایت RAM) فایل swap می‌سازد.
- محیط پایتون، کتابخانه‌های سیستمی مرورگر و خود مرورگر را برای همان کاربر نصب می‌کند (Chrome روی amd64، در غیر این صورت Chromium).
- دستور کمکی `monitor` را می‌سازد، تنظیمات را اعتبارسنجی می‌کند و سرویس systemd را با محدودیت منابع و سخت‌سازی امنیتی فعال می‌کند (`Restart=always`).

### به‌روزرسانی سرور با نسخهٔ جدید کد

همان سه کار بالا را تکرار کنید: `package` و `scp` روی ویندوز، سپس `unzip -o …` و `sudo bash monitor-src/deploy/install_service.sh` روی سرور.
- `monitor-config.json`، دیتابیس، سایت‌های اضافه‌شده با ربات و تاریخچه **دست نمی‌خورند**؛ فقط کد عوض می‌شود و سرویس ری‌استارت می‌شود.
- برای اینکه تنظیمات بستهٔ جدید جای تنظیمات سرور را بگیرد (معمولاً لازم نیست): `sudo FORCE_CONFIG=1 bash monitor-src/deploy/install_service.sh`

```bash
sudo journalctl -u monitor-service -f       # لاگ زنده
monitor validate                            # فهرست سایت‌ها و بررسی تنظیمات
monitor history                             # تاریخچهٔ تغییرات
monitor inspect https://example.com         # همهٔ دستورات برنامه با «monitor»
sudo systemctl restart monitor-service      # ری‌استارت
```
`monitor once --dry-run` روی سرور امن است، چون حافظهٔ جداگانه دارد. فقط `chat-id` را وقتی سرویس با توکن فعال در حال اجراست اجرا نکنید (هر دو پیام‌های ربات را می‌خوانند)؛ اول `sudo systemctl stop monitor-service`.

حذف کامل: `sudo systemctl disable --now monitor-service && sudo rm -rf /opt/monitor /etc/systemd/system/monitor-service.service /usr/local/bin/monitor`

> اگر سرور در ایران است و تلگرام فیلتر است، `telegram.proxy` را تنظیم کنید. بهتر است سرور خارج از ایران باشد.

## سایت‌های دارای محافظ ضدربات (خطای 403)

بسیاری از سایت‌های دولتی، دانشگاهی، سفارت‌ها و موسسه‌هایی مثل گوته پشت سرویس‌هایی مثل **Akamai Bot Manager** یا Cloudflare هستند. این سرویس‌ها:
- برنامه‌های معمولی را از روی «اثر انگشت TLS» تشخیص می‌دهند. روش `impersonate` این مشکل را حل می‌کند.
- اگر از یک IP درخواست‌های ربات‌گونهٔ زیادی ببینند، **کل آن IP** را برای مدتی (معمولاً چند ساعت) مسدود می‌کنند؛ حتی مرورگر واقعی.

**توصیه‌ها:**
1. برای سایت‌های ظرفیتی، داده‌های پشت صفحه (API) را پایش کنید (مثل گزینهٔ «🎓 آزمون‌های گوته»). هر بررسی فقط یک درخواست کوچک است.
2. فاصلهٔ بررسی را برای این سایت‌ها ۲ تا ۳ دقیقه بگذارید (ربات خودش پیشنهاد می‌دهد). بیدارباش جبران چند دقیقه تأخیر را می‌کند.
3. اگر سایتی خطا بدهد، فاصلهٔ بررسی خودکار دو برابر می‌شود (تا ۳۰ دقیقه) و بعد از اولین موفقیت به حالت عادی برمی‌گردد.
4. **پروکسی پشتیبان (خودکار):** اگر سایتی IP سرور را مسدود کند (403/429 یا صفحهٔ «Access Denied»)، همان بررسی خودکار از طریق **پروکسی پشتیبان** تکرار می‌شود و اگر جواب داد، آن سایت از آن به بعد از همین مسیر بررسی می‌شود (در کارت سایت: «🛡 از طریق پروکسی پشتیبان»). اگر مسیر پروکسی هم مسدود شود، دوباره مسیر مستقیم امتحان می‌شود. هنگام افزودن سایت هم همین کار انجام می‌شود.
   - **پیش‌فرض (خودکار): Cloudflare WARP روی همین سرور (رایگان)** — اگر روی پورت `40000` فعال باشد، بدون هیچ تنظیمی استفاده می‌شود:
     ```bash
     curl -fsSL https://pkg.cloudflareclient.com/pubkey.gpg | sudo gpg --yes --dearmor -o /usr/share/keyrings/cloudflare-warp-archive-keyring.gpg
     echo "deb [signed-by=/usr/share/keyrings/cloudflare-warp-archive-keyring.gpg] https://pkg.cloudflareclient.com/ $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/cloudflare-client.list
     sudo apt-get update && sudo apt-get install -y cloudflare-warp
     warp-cli registration new
     warp-cli mode proxy
     warp-cli connect
     ```
     حالت proxy فقط همان سایت‌ها را از WARP عبور می‌دهد و به SSH و بقیهٔ سرور کاری ندارد. ممکن است بعضی سایت‌ها IPهای WARP را هم مسدود کنند.
   - **مطمئن‌ترین، proxy خانگی/موبایل (پولی):** آدرسی مثل `http://user:pass@host:port` بگیرید و در ⚙️ تنظیمات ← «✍️ پروکسی دلخواه» وارد کنید (برای همهٔ سایت‌های مسدودکننده)، یا در ویرایش یک سایت ← 🌐 پروکسی (فقط همان سایت).
   - در ⚙️ تنظیمات می‌توانید پروکسی پشتیبان را خاموش کنید.

## نکات سرعت و دقت

- **فاصلهٔ بررسی:** برای صفحات حساس (نوبت‌دهی) ۳۰ تا ۶۰ ثانیه و برای بقیه ۲ تا ۵ دقیقه مناسب است. فاصلهٔ خیلی کم ممکن است باعث مسدود شدن IP شود.
- **HTTP در برابر مرورگر:** اگر `inspect` نشان دهد HTTP کافی است، `engine: "http"` سریع‌ترین گزینه است. حالت `auto` در صورت نیاز خودش به مرورگر می‌رود و همان را نگه می‌دارد (`reset` این انتخاب را پاک می‌کند).
- **هشدار کاذب:** زمان‌های نسبی («5 mins ago»، «۳ ساعت پیش»)، زمان مطالعه و پخش‌کنندهٔ ویدیو خودکار حذف می‌شوند. اگر بخش دیگری از صفحه مدام عوض می‌شود (ساعت، شمارندهٔ بازدید)، آن را با `exclude_selectors` یا `ignore_patterns` حذف کنید. برای سایت‌های خبری حالت «📰 تیترهای جدید» را انتخاب کنید.
- **تغییر selector:** بعد از تغییر selector یا تنظیمات مرتبط، اولین بررسی بی‌صدا یک baseline جدید ذخیره می‌کند (پیام «همه‌چیز عوض شد» نمی‌آید).
- **کش CDN:** اگر سایت پشت CDN است و تغییرات با تأخیر دیده می‌شوند، `cache_bust: true` را امتحان کنید.

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| `selector ... matched nothing` | ساختار صفحه عوض شده یا صفحه مسدود است. `inspect` را دوباره اجرا کنید. |
| `content too short` | selector اشتباه است، یا سایت با جاوااسکریپت ساخته می‌شود (`engine: "browser"`)، یا ربات مسدود شده است. |
| `HTTP 403` / `looks like Cloudflare` | در ربات «🧪 تست دسترسی» را بزنید. اگر هیچ روشی (مستقیم و از طریق پروکسی) جواب نداد: معمولاً مسدودی موقت است؛ فاصلهٔ بررسی را بیشتر کنید و اگر طولانی شد پروکسی خانگی/موبایل بگذارید (بخش «سایت‌های دارای محافظ»). |
| `SOCKS proxies need the aiohttp-socks package` | اسکریپت نصب را دوباره اجرا کنید (این کتابخانه حالا جزو `requirements.txt` است). تا آن موقع روش «شبیه‌ساز کروم» خودکار جایگزین می‌شود. |
| `no browser could be launched` | `patchright install chromium` |
| `TLS/SSL error` | `engine: "browser"` یا `verify_ssl: false` |
| `Telegram API error 401` | توکن اشتباه است. |
| `chat not found` | Start را در ربات نزده‌اید یا `chat_id` اشتباه است (`chat-id` را اجرا کنید). |
| `cannot reach Telegram` | تلگرام فیلتر است: `telegram.proxy`. پیام‌ها در صف می‌مانند و بعداً ارسال می‌شوند. |
| هیچ پیامی نمی‌آید | `history` را ببینید؛ اگر تغییری ثبت شده ولی ارسال نشده، خطای ارسال در لاگ آمده است. |

## تست‌ها

```bat
.venv\Scripts\python -m unittest discover -s tests -v
```
۷۸ تست خودکار شامل این موارد است:
- استخراج متن، جدول و محتوای پنهان؛ مقایسهٔ کلمه‌به‌کلمه؛ escape شدن HTML.
- تقسیم پیام‌های طولانی؛ تلاش مجدد هنگام قطعی تلگرام (بدون از دست رفتن پیام حتی با ری‌استارت)؛ محدودیت نرخ (429).
- cooldown؛ خزش (صفحهٔ جدید، تغییرکرده، حذف‌شده و فایل PDF)؛ RSS و خبرها.
- سوییچ خودکار به مرورگر برای صفحات جاوااسکریپتی.
- پنل تلگرام: رد کاربران غریبه، تشخیص سازندهٔ کانال به‌عنوان مدیر، افزودن سایت با دکمه‌ها از ابتدا تا ارسال تغییر به کانال، توقف/ویرایش/خزش/حذف، پشتیبان و بازگردانی، و مسدود بودن آدرس‌های شبکهٔ داخلی.
- سایت‌های ظرفیتی: آزمون‌های گوته (API و فیلتر شهر)، گزارش «⛔ تکمیل ← ✅ قابل رزرو» با 🚨، بیدارباش و قطع آن با «دیدم»، جایگزینی خودکار HTTP ← شبیه‌ساز کروم، کاهش سرعت بعد از خطا، تست دسترسی و تنظیم proxy از ربات.
- پروکسی پشتیبان: سایتی که IP سرور را مسدود کرده، از طریق یک پروکسی SOCKS5 واقعی (شبیه‌سازی‌شده در تست) بررسی می‌شود و همان مسیر حفظ می‌شود؛ تست دسترسی دو مسیره.
- سایت خبری: حالت تیترهای جدید (جابه‌جایی و تغییر زمان‌ها پیام نمی‌سازد)، حذف زمان‌های نسبی، برچسب درست لینک‌ها، پست‌های تلگرام بدون امضا و پاورقی، پیشنهاد خودکار تبدیل صفحهٔ پرتغییر.
- ربات: منوی ثابت، دستورات گروه، باز شدن پیام جدید زیر گزارش‌ها، هشدار سایت تکراری، لغو سؤال باز با ارسال لینک، افزودن سایت مسدود و پیام «حالا باز می‌شود»، عکس صفحه.
